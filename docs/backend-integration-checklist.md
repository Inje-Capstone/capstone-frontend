# 백엔드·AI 연동 요청 사항 — 2026-11-02

아래 내용은 현재 프론트 연결 상태에 대한 요청입니다. 백엔드에 기능이 없다고 단정하는 목록은 아닙니다. 구현되어 있다면 병합된 브랜치/배포 주소와 확정 API 명세를 공유해 주세요. 프론트에서 임의의 REST URL을 추가하지 않았습니다.

## 우선 1: 로컬 개발 출처의 API 호출 허용

현재 확인한 CorsConfig는 `https://injecapstone.com`만 허용합니다. 로컬 화면에서 원격 API를 호출할 수 있도록 개발용 허용 출처를 명시적으로 구성해 주세요.

- `http://localhost:5173`
- `http://127.0.0.1:5173`
- 태블릿/LAN 테스트가 필요하면 실제 프론트 PC의 `http://<개발 PC의 IPv4>:5173`도 별도 허용
- `Authorization`, `Content-Type` 헤더와 필요한 HTTP 메서드, OPTIONS preflight 처리 확인
- 회원 탈퇴 메서드가 DELETE로 확정된다면 해당 메서드도 CORS 허용에 포함
- 현재 프론트는 Bearer JWT를 사용합니다. 쿠키 인증이나 credentials 정책을 임의로 바꾸지 않습니다.

이는 서버가 로컬 파일·디스크를 읽게 하는 권한이 아닙니다. **로컬 개발 프론트에서 서버 API로 보내는 요청의 Origin을 허용하는 작업**입니다. 전체 출처 `*` 대신 합의한 개발 주소만 추가해 주세요.

## 우선 2: OAuth 개발 환경 복귀 주소

Google/Kakao의 공급자 콜백과 프론트 최종 복귀 주소를 구분해 주세요. 현재 설정은 최종 프론트 복귀가 배포 도메인 기준입니다. 로컬 소셜 로그인 검증을 위해 개발 환경의 FRONTEND_URL 또는 검증된 개발 복귀 주소 구성이 필요합니다. 사용자 입력 URL을 무조건 신뢰하는 redirect는 요청하지 않습니다.

## 우선 3: 퀴즈·탈퇴 계약과 어댑터

현재 `src/integrations/backendPorts.ts`에는 포트 정의만 있고, `configureBackendPorts(...)`를 호출해 실제 어댑터를 등록하는 코드는 없습니다. 이미 API가 준비됐다면 명세를 공유해 주세요.

- 퀴즈: 날짜별 저장 문제 조회, 최대 7일 기록 조회, 답안 제출·서버 채점·해설·보상·풀이 기록 조회
- 각 요청/응답 DTO, 성공/실패 상태, ID 형식, 한국 시간 기준 날짜 정책
- 중복 제출의 처리 정책. 현재 프론트는 같은 답안 재시도 시 submissionId를 재사용하며 서버 채점 결과만 표시합니다.
- 서버가 확인한 포인트 잔액의 제공 여부. 프론트는 자체 채점이나 고정 포인트 지급을 하지 않습니다.
- 회원 탈퇴: 실제 URL/메서드·본인확인·성공 응답·실패/재시도 정책. 서버 성공 확인 후에만 프론트 정규화 결과 `{deleted:true}`로 변환합니다. 이것은 서버 DTO를 강제하는 규격이 아닙니다.

프론트 화면 모델은 `src/types/quiz.ts`에 있습니다. 백엔드 DTO가 다르면 확정 명세를 기준으로 어댑터에서 변환하겠습니다. AI 문제 생성 API를 저장 퀴즈 조회/채점 API로 대신 사용하지 않습니다.

## 우선 4: 녹화 영상과 AI 실제 연결

현재 `VITE_AI_DEMO_MODE=true`이면 경기·용어·카드·장면·매치업·채팅의 준비된 데이터를 사용합니다. 이는 실제 로그인 여부와 별개인 기존 배포 설정이며, 서버 인증이 연결됐다고 AI도 연결된 것은 아닙니다.

- 발표에 사용할 녹화 영상의 HTTPS 제공 주소와 game_id
- 영상 재생/탐색을 위한 Range 응답 지원, 필요 시 미디어 CORS 및 서명 URL 만료 정책
- AI 직접 호출인지 Spring 중계인지 최종 경로와 인증 정책
- 카드·용어·장면·매치업·챗봇의 확정 DTO 및 sample
- 시간 단위(초/ms), 영상 시작점·클립 오프셋, event/card ID, 분석 결과 갱신 방식
- 실제 경로와 샘플 검증 후에만 AI 시연 설정을 끄고 실제 API로 전환

현재 경기·AI 대체 데이터를 무조건 삭제하면 발표 화면이 빈 상태가 될 수 있어 이번 정리에서는 유지했습니다. 가상 데이터임을 표시하는 문구도 실제 데이터로 오인되지 않도록 남겼습니다.

## 후속 기능

- 비밀번호 재설정 메일·토큰 검증·비밀번호 변경 API와 오류 정책
- 상점 상품·가격·포인트 잔액·구매·보유 아이템·착용 API. 임의 가격·로컬 포인트 차감·가상 구매 코드는 제거했고 현재는 디자인 미리보기와 준비 중 상태만 표시합니다.
- 관심 카테고리/시청 후 복습 설정/영상 이어보기의 기기 간 동기화가 필요하면 저장 주체와 API 협의. 현재 이 항목은 기기/탭 저장입니다.

## 확인 순서

1. CORS 반영 후 로컬에서 기존 계정 로그인 → 온보딩 상태 → 내 정보 조회.
2. 세션 만료/401·오류 재시도와 로컬 OAuth 복귀.
3. 확정된 퀴즈/탈퇴 어댑터 등록 후 별도 테스트 계정으로 검증.
4. 실제 영상·AI 타임코드 대조 후 시연 데이터 모드 해제.
5. PR 검토 후 develop 병합. 현재 CD 설정에서는 develop의 CI가 성공하면 배포가 실행됩니다.

## Git 및 로컬 검증 도구 경계

`work/ui-harness.cjs`는 프론트 저장소 밖에 있는 로컬 검증 프록시입니다. 5174에서 API 응답과 offline/online 이벤트를 대체하며, 오른쪽 아래 TEST 버튼은 이 도구에서만 삽입됩니다. `src`, `public`, 배포 `dist`에 TEST 버튼/검증 스크립트가 없는 것을 검사했습니다. 5173 및 배포 빌드에는 이 도구가 포함되지 않습니다.
